# 蒸馏计划2完整词根 - 成果说明

第二套模型：同一批词（24,149，来自 run1 的 `words_all.txt`）产"真实词根不切碎"标签，训练模型2，与模型1（易记小段版）并存供 app 双视图。

## 管线（相对 run1 的关键差异）

```
select_words(沿用 run1 的 words_all.txt)
  -> generate.py   agnes-2.5-flash, 关 thinking, 批量20, temp=0
  -> repair_segments.py   不丢原始输出, 对齐DP重拼接 (三态: direct/repaired/unfixable)
  -> postprocess.py       校验 + 一致性修复 (72% -> 83%)
  -> preprocess_rules.py  对结果的预处理 (规则按文档顺序逐条套)
  -> split_data.py 90/5/5 -> train_model.py -> eval_model.py
```

## 结果

- 解析 23,697/24,149 (98.1%)，unparsed 452 存 `unfixed.jsonl` 备查，**0 条 unfixable**
  （用户判断正确：非拼接全是差一个字母，对齐 DP 全部改对）
- 规则预处理改动 2,591 词 (10.9%)，0 切分失败，一致性 72.2% -> 73.0%
- 模型2（规则清理后标签训练，torch/CharBiLSTM，ONNX 部署）：测试集 gap F1 **0.720**、词级完全一致 **55.4%**，
  阈值 **0.44**（POS_WEIGHT=1.5，均扫自 `sweep_pos_weight.py`；见"run2 特有经验 #6"）
  （比 run1 的 0.825/60.4% 低，因为预期：真实词根 + 规则切分更难拟合；输出风格由规则保证）

## 对结果的预处理（`rules.py` 规则引擎，已接入 segment.py 推理端）

文档顺序逐条：1字母合并 / ify / at.ion->ation / ization / cata / ed / ment / us / ist / tion / er / ia / etic / exo / devas / iatric。
示例词全部命中（diuretic、magnetically、cybernetic、exoticism、devastatingly、pediatric、tipper、forger、tilapia、hernia、troubadour、catamaran、talus、fortify 等）。

实现时做的裁决（用户已拍板"误伤无所谓"）：
- `er` 规则加守卫：仅当原切分已暗示 er 边界（末段为 `r` 或以 `er` 结尾、且非单段）才强制切，
  避免 `temper/ulcer/cider` 这类单段词被错切；代价是 `wallpaper->wallpap.er` 类复合词误伤。
- `mag.net.ic->magn.etic`（magnetic 类）与 `cyber.net.ic->cyber.netic` 在通用规则上互相矛盾：
  实现为 `net+ic->netic` 通用 + `mag.net.ic` 特判（n 并入前段）。
- `di.u.retic` 是 etic 规则的例外，在 1字母 规则里特判为 `u` 并入 `re`->`ure`，留 `tic`。
- `troubadour` 与 ia 规则无共同模式，按精确词特判。
- ia 词尾、ed/us/ist/ment/tion/cata/etic 等按文档字面全量套用。

## run2 特有经验

1. **agnes-2.5-flash 关 thinking 可用**（`chat_template_kwargs: {"enable_thinking": false}`，
   rt=0、格式 100%），词源判断比 2.5 之外的版本更强；`reasoning_effort=none` 报 422 无效。
2. **非拼接率实测 828/24,149 ≈ 3.4%**，全是对齐 DP 可修的差一字母错误，用户预判正确，
   所以"修而不是丢"让可用率 96.1% -> 98.1%。
3. **推理端必须与训练端共用同一套规则**：eval 与 segment.py 都套 `apply_rules` 后再比对，
   否则评估数字与 app 实际显示不一致。
4. 阈值扫描要在"套规则后的输出"上做（eval 与 app 一致的口径）。
5. 规则切分让训练目标更激进，val_bce 0.1850 -> 0.2182，fidelity 略降是预期的风格换优。
6. **正负样本不平衡**：真实切分 gap 中 positive(cut) 仅 17.46%（~1:4.5，用户预判 1:3~1:4 正确）。用
   `pos_weight` 加权 BCE，并用 `sweep_pos_weight.py` 扫 `1.3/1.5/1.8/2.0`：四者皆满足
   exact≥54.5% 且几乎无阈值悬崖，最均衡的是 **1.5**（F1 平台中心最高 .718、平台宽 0.29、最佳F1 .720）。
   阈值取该平台中心 **0.44**，避免"误切"与"低置信不切"两头受损。
7. **训练必须可复现**：`train_model.py` 设 `torch.manual_seed(0)`（numpy 之外 torch 自带 Embedding/LSTM
   初始化也要固定），否则同权重每次跑出不同指标（曾出现 53.2% vs 56.3% 的假差异）。

## 接入 app（蒸馏模型2）

- `app/distill_cutter.py`：模型封装（onnxruntime 加载 `model.onnx` + 规则），权重 `蒸馏计划2完整词根/output/model.onnx`，
  推理阈值 0.44；规则经 importlib 从 `蒸馏计划2完整词根/rules.py` 单一来源加载（改规则两端同步生效）。
- `app/main.py`：lifespan 加载 `app.state.distill_cutter`；`/api/lookup` 与 `/api/lookup_expand`
  精确命中时渲染 `templates/partials/_distill_result.html`（标题"蒸馏模型2"），插在"词根词缀分析"之后并列显示。
- `static/style.css`：`.distill-analysis` 绿色系样式区分。
- 权重缺失时优雅降级（distill_cutter=None，不渲染该块）。

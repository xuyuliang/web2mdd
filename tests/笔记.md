# 查词拆词流水线改进方案

## 一、现状

当前流水线 `test-word-cut.py` 包含两阶段：

1. **Stage1 crosstem** — 使用 `eng_derivations.json` 逆向索引追溯派生链（如 `prediction → predict.ion`）
2. **Stage2 词根字典** — 使用 `etym-dictionary.json` 贪心最长词根匹配（如 `predict → pre.dict`）

## 二、新增数据文件

### 2.1 `data/affixes.json` — 补充英语常见前后缀

**来源：** `\数据资料\morphemes.json`（3034 前缀 + 850 后缀）

**生成方式：** 写 `scripts/build_affixes.py`
- 遍历 morphemes.json，筛选 `loc` 为 `prefix` 或 `suffix` 的条目
- 提取 root（如 `-able`、`pre-`）、form、meaning、origin
- **去重：** 去掉 root 首尾的 `-` 后，检查是否已存在于 `etym-dictionary.json` 的词根中
  - 若有 → 跳过，保留字典原条目（含 `-`, `*`, `=` 符号）
  - 若无 → 写入 `affixes.json`，格式兼容 `{"entries": [{"roots": "...", "langCode": "...", "meaning": "..."}]}`

**注意：** `etym-dictionary.json` 的词根包含特殊符号表示变形：
- ``-`` 或 ``*``：可选后缀（可加可不加）
- ``=``：主格固有字符，不可分割

示例：根 `iri, -d, -do, =s, -t`
- `iris`：s 来自 `=s`，必须整体切分为 `iris`
- `irit`：t 可能属于根（iri）或后缀（itis），优先切为 `iri.itis`
- `iridescent`：虽有 `-d`，但 escent 是独立后缀，应切为 `irid.escent`

`parse_roots` 会去掉 `-`、`*`、`=` 后提取纯词根形式用于匹配。去重时 morpheme 的 root 去掉首尾 `-` 后若落在该集合中即视为冲突。
- 无法确认含义的，标注 `"langCode": "?"`

**示例条目：**
```json
{"roots": "-tion", "langCode": "L", "meaning": "action/state (noun-forming)"}
{"roots": "-ness", "langCode": "E", "meaning": "state/quality (noun-forming)"}
{"roots": "out-",  "langCode": "E", "meaning": "beyond/external"}
```

### 2.2 `data/short_words.json` — 短单词表

**来源：** `\数据资料\oldCOCA60000.txt`

**生成方式：** 写 `scripts/build_short_words.py`
- 读入全部词汇，筛选长度 2–5 的单词
- 全小写，去重
- 导出为 JSON 对象（O(1) 查找）：`{"bunk": true, "act": true, ...}`

**作用：** 贪心匹配后，未识别的残余片段若命中短单词表，不包裹 `[]`。同时将短单词加入 root_index（按最长匹配优先），让 `debunk` 切出 `de.bunk` 而非 `de.bun.[k]`。

### 2.3 `data/word_derivations.json` — 裁剪后的派生数据

**来源：** `\数据资料\eng_derivations.json`（70MB, 258K 条）

**现状：** 只有 25/125 GRE 词命中。每条含 `pos`、`derives_to`、`derived_from`，但代码只需逆向索引。

**裁剪方式：** 遍历原文件，只提取：
```json
{
  "prediction": {"base": "predict", "affix": "ion", "affix_type": "suffix"},
  "action":     {"base": "act",     "affix": "ion", "affix_type": "suffix"},
  ...
}
```
约 219K 条映射（70MB → ~15MB）。

Stage1 的 `trace_derivation` 改为只查此文件，不再需要完整的 `deriv` 字典。

## 三、Pipeline 改动

| 改动 | 说明 |
|---|---|
| `build_root_index` | 合并加载 `etym-dictionary.json` + `affixes.json` + 短单词（作为最低优先级词根），按长度降序排列 |
| `segment_word` | 匹配完词根后，残余片段查 `short_words.json`，命中则不包 `[]` |
| `trace_derivation` | 只查 `word_derivations.json`（不再需要 `deriv` 全局变量） |
| 启动加载 | 从 3 个文件（deriv 70MB + rev_index 内存 + dict）→ 2 个文件（word_deriv ~15MB + roots ~2MB + affixes ~200KB + short_words ~10KB）|

## 四、构建脚本

创建 `scripts/` 目录，三个独立脚本：
- `scripts/build_affixes.py` — 从 morphemes.json 生成 affixes.json（含 etym-dictionary 去重检查）
- `scripts/build_short_words.py` — 从 oldCOCA60000.txt 生成 short_words.json
- `scripts/build_word_derivations.py` — 从 eng_derivations.json 生成 word_derivations.json

## 五、讨论记录

### 5.1 word_derivations.json 大小

逆向索引朴素格式（`{"word": {"base": "...", "affix": "...", "affix_type": "..."}}`）每条 ~75 字节，219K 条 → ~16MB。

实际改用分列压缩格式，字段名只出现一次：
```json
{
  "words":   ["prediction", "action", "aberration", ...],
  "bases":   ["predict",    "act",    "aberrate",   ...],
  "affixes": ["ion",        "ion",    "ion",        ...],
  "types":   ["s",          "s",      "s",          ...]
}
```
类型用 `"s"` / `"p"` 代替 `"suffix"` / `"prefix"`，每条约 20 字节 → ~**4-5MB**。

### 5.2 短单词表粒度

只保留 **3–5 字母**的单词（2 字母干扰太大）。

### 5.3 去重规则

etym-dictionary 优先。`parse_roots` 处理 `iri, -d, =s` 等符号后得到集合 `{iri, d, s}`，morpheme 的 root 去掉首尾 `-` 后若落在此集合中即为冲突，跳过。义项不追加，morphemes.json 只补充 etym-dictionary 没有的内容。

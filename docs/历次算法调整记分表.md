# 历次算法调整记分表

## 评分标准

- **测试集一（旧套）**：GRE-words.txt（125 词）
  - 标准答案 A：`tests/human_standard.txt`（人工标注，基于真实词源）
  - 标准答案 B：`tests/gre_standard.json`（标准切分 + stage1）
- **测试集二（新套）**：newGREwords.txt（120 词）
  - 标准答案：`tests/newGREwords_standard.json`（整词加 `[]` 未切分，对应 newGREwords 标准答案）
- **打分方式**：分段精确匹配（文本 + 段边界 + 已知/未知状态逐段对比）

## 版本记录

### v1.6 — 全路径搜索评分计入频率加分（整链比较）

**变更**：`_best_path_ltr` / `_best_path_rtl` 的 memo 状态从 `(cov, segs, edge)` 扩展为 `(total, segs, edge)`，`total` 在递归中累加 `_candidate_score`（含高频频率加分），使前瞻按整条链比较而非仅覆盖度；`_select_best_ltr/_rtl` 决策与前瞻口径一致。加分公式：`bonus = 0.5 + 0.25 * log2(n / 3)`（n≥3），高频表改用 `数据资料/highfreq.json`。

**触发案例**：`gregarious` 从 `greg.ar.i.ous` 改善为 `greg.ar.ious`（整链下 ious 胜出 ous）

| 指标 | 值 |
|---|---|
| 旧套 A（vs_human） | 57 / 125（45.6%） |
| 旧套 B（vs_standard） | 52 / 125（41.6%） |
| 旧套 test-word-cut 命中 | 121 / 125 |
| 新套（vs newGRE 标准） | 35 / 120（29.2%） |

**分析**：本次会话内三个阶段对比：

| 阶段 | 旧套A | 旧套B | test-word-cut | 新套 |
|---|---|---|---|---|
| 基线（旧表 +0.5） | 59 | 57 | 123 | 44 |
| 阶段A（highfreq +0.5） | 54 | 53 | 121 | 38 |
| 阶段B（highfreq +频率） | 53 | 47 | 121 | 36 |
| v1.6（highfreq +整链频率） | 57 | 52 | 121 | 35 |

整链比较相比阶段B显著回升（53→57、47→52），但仍低于旧表基线——highfreq.json（532 条）覆盖不如旧表全。

### v2.2 — 吞音（元音重叠 elision 边）

**变更**：新增 `elide` 边——候选段尾字符为元音时，扫描自该元音起的长段候选，两段共享该元音 1 字符（如 `sangui+ine`、`ated=ate+ed`）。边覆盖 `Lm+Lo−1`，权 `Lm+Lo−1−2×SEG_COST`，与"段+gap+段"等值（重叠字符不重复计覆盖）。c2 短根护栏豁免（重叠视为邻接）。输出两段文本共享该字符。

**触发案例**：`inculcate → incu.ulc.ate`（`incu` 与 `ulc` 共享 `u`）

| 指标 | 值 |
|---|---|
| 旧套 A（vs_human） | 59 / 125（47.2%） |
| 旧套 B（vs_standard） | 47 / 125（37.6%） |
| 旧套 test-word-cut 命中 | 124 / 125 |
| 新套（vs newGRE 标准） | 40 / 120（33.3%） |

### v2.1 — 垫音（linking 吸收边）

**变更**：新增两条吸收边，语义为"gap 字母不扣分并并入邻段"（不奖 +1 覆盖，仅免除 GAP_COST）：
- `absorb_r`（右吸收）：段尾为元音且左邻为辅音时，尾元音并入左段，边 `[i→i+Lm+1)`，权 `Lm−SEG_COST`
- `absorb_l`（左吸收）：gap 为辅音且右邻为元音时，并入右段，边 `[i→i+Lm2+1)`（自 gap 位起跳，权 `Lm2−SEG_COST`）

**修正**：初版 `absorb_l` 在"gap 边之后的状态"生成，导致被吸收字符被 gap 与吸收边双重覆盖（如 `extant → ex.t.tant`，17 词重叠）；改为自 gap 位本身起跳、作为 gap 边的替代，消除双覆盖。

| 指标 | 值 |
|---|---|
| 旧套 A（vs_human） | 59 / 125（47.2%） |
| 旧套 B（vs_standard） | 47 / 125（37.6%） |
| 旧套 test-word-cut 命中 | 124 / 125 |
| 新套（vs newGRE 标准） | 40 / 120（33.3%） |

**分析**：吸收边使段文本变长（`deluge→delu.ge`、`sanguine` 整词一段），对依赖"留 gap 为 `[x]`"的标准套略损；为消除双覆盖修正 absorb_l 后分数回落。曾测试两种变体：
- 边界条件即可（v2.1/v2.2，用户选择）：59/47
- 右吸收要求后继为已匹配段 + 左吸收禁词首：60/49

两者均接近无垫音基线（v2.0 60/50），垫音对考试分整体中性偏负。

### v2.0 — 一次性全局最优 DAG 切分（替换逐段贪心 + 交替循环）

**变更**：`_segment_word` 不再用 `_match_one_pass`（RTL 定锚 + LTR/RTL 交替逐段提交），改为单个正向 DP（Viterbi/最大路径）一次性求全局最优：
- 状态 `(pos, prev_matched)`（`prev_matched` 供 ≤2 字母短根护栏：须段首或紧邻已匹配段）
- 边集：普通段 `[i→i+L)` 权 `L−2+sec`；跳 gap `[i→i+1)` 权 `−1`
- 评分 `primary = 覆盖 − 2.0×段数 − 1.0×gap字符`；`secondary = Σ频率加分 − Σopt惩罚(0.5)`；仲裁链 primary → secondary → −段数 → −边缘短根数 → 末段更长
- memo 存 `(key 元组, backpointer)` 回溯重建整条路径；未知连续段仍经 `_merge_unknowns` 合并
- 删除：`_match_one_pass`、`_best_path_ltr/_rtl`、`_select_best_ltr/_rtl`、`_can_match_short_root[_rtl]`、`_find_candidates_ltr/_rtl`、`_has_exact_root`、交替循环
- 保留：整词 ≤1 音节预检、Stage1 派生管道、`_pos_allowed`、输出格式；≤1 音节"剩余留块/循环跳过"规则删除，交给评分处理

**触发案例**：`corroborate` 从 `corr.ob.or.ate`（v1.x）→ `cor.robor.ate`

| 指标 | 值 |
|---|---|
| 旧套 A（vs_human） | 60 / 125（48.0%） |
| 旧套 B（vs_standard） | 50 / 125（40.0%） |
| 旧套 test-word-cut 命中 | 124 / 125 |
| 新套（vs newGRE 标准） | 40 / 120（33.3%） |

**分析**：四套全面高于 v1.7（52/48/123/32），全局最优 + 分段代价有效消除过度切分；旧套 A 为历史新高。

### v1.5 — 全路径搜索评分（替代 1-step lookahead）

**变更**：
1. 用 `_best_path_ltr` / `_best_path_rtl`（带 memo 的递归全路径搜索）替代 `_best_next_info` / `_best_prev_info`（1-step lookahead）
2. 评分公式：`score = len(current) + max_future_coverage`，其中 max_future_coverage 是对所有候选分支走到底算出的最优总覆盖
3. 保留上一版本的所有其他改动（无 affix 加分、strip 前缀、RTL 定锚）

**触发案例**：`apotheosis` 保持 `apo.the.osis`

### v1.3 — RTL 首轮只定右锚点（首个匹配后即停）

**变更**：`_match_one_pass` RTL 方向匹配到第一个候选后立即 break，不再继续向左扫描。剩余左侧文本整体标记为 unknown，交由交替循环的 LTR 处理。

**触发案例**：`apotheosis` 从 `ap.othe.osis` 改善为 `apo.the.osis`

| 指标 | 值 |
|---|---|
| 精确匹配 | 52 / 125 |
| 精确匹配率 | **41.6%** |
| 失配 | 73 |

**分析**：RTL 全扫描虽然有时吞了左侧空间，但同时也帮 LTR 确立了多级边界。只定右锚点后，LTR 面对大块未知段更容易误切。多数新失配源于 LTR 首轮选错了根。

---

### v1.2 — 同分选长根（self-first）+ 前缀尾部连字符剥离

**变更**：
1. `_select_best_ltr` / `_select_best_rtl` 平局时从选短根改为选长根（self-first）
2. `_parse_roots` 中 `lstrip("-*")` → `strip("-*")`，剥离前缀尾部连字符（如 `dem-` → `dem`）

**触发案例**：`demagogue` 现正确拆为 `dem + agogue`（之前 `dem-` 因尾部 `-` 无法匹配）

| 指标 | 值 |
|---|---|
| 精确匹配 | 55 / 125 |
| 精确匹配率 | **44.0%** |
| 失配 | 70 |

**分析**：同分选长根导致整体分片质量下降（52.8% → 44.0%），说明优先让下一步多匹配的策略更优。

### v1 — 交替方向贪心匹配（初始版本）

**算法概要**：
- 初始 RTL 扫描整词 → 进入交替循环（LTR → RTL → LTR → ...）
- 1 步前瞻（lookahead）评分 + affix 加分
- `_match_one_pass` 内：匹配后剩余 ≤1 音节 → 整块留未知，停止
- 交替循环：≤1 音节且不在 root_index 中的段 → 跳过

| 指标 | 值 |
|---|---|
| 精确匹配 | 65 / 125 |
| 精确匹配率 | **52.0%** |
| 总失配 | 60 |

**失配分类**：

| 类型 | 计数 | 示例 | 根因 |
|---|---|---|---|
| 短前缀丢失 | ~15 | `a(ver)`, `e(rudite)`, `oc(clude)`, `per(cipient)`, `pro(clivity)`, `ne(farious)` | RTL 优先匹配后缀后，剩下段 ≤1 音节被跳过；短根规则（≤2字）也阻挡 |
| 剩余1音节跳过致前缀丢失 | ~12 | `co(al)esce`, `in(cul)cate`, `(in)effable`, `(in)veterate` | RTL 切走后缀后 1 音节剩余直接被跳过，等不到 LTR 找前缀 |
| 无根整词/碎片 | ~8 | `chicanery`, `harangue`, `mettlesome`, `raconteur`, `craven`, `austere` | 词典中无匹配；算法找到的根是 spurious match |
| 残留单字符 | ~10 | `del[u]ge`, `denig[r]ate`, `[h]ar[ang]ue`, `ext[r]avagance` | 逐字符跳过 + 音节检查只防连续 >1 组的情况 |
| 错配词根 | ~10 | `sanguine`→`san.gui`(×) vs `sangu.ine`(✓), `sycophant`→`sy.coph`(×) vs `syc.o.phant`(✓) | root_index 匹配了字面相似但词源不同的根 |
| 标准粒度过细 | ~5 | `turp.i.tude` vs `turpi.tude`, `voc.i.fer.ous` vs `voci.fero.us` | 算法聚合形式合理但标准不一致 |

**主要短板**：
1. 短前缀（≤2字母）无法被识别
2. 1音节剩余跳过规则同时阻挡了有效前缀搜索
3. root_index 缺少部分常用词根（如 `locut`, `plac`, `calc`, `calc` 等）
4. 逐字符跳过产生大量单字符残留

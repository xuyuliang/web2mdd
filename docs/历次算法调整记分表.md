# 历次算法调整记分表

## 评分标准

- **测试集**：GRE-words.txt（125 词）
- **标准答案**：`tests/human_standard.txt`（人工标注，基于真实词源）
- **打分方式**：分段精确匹配（文本 + 段边界 + 已知/未知状态逐段对比）

---

## 版本记录

### v1.5 — 全路径搜索评分（替代 1-step lookahead）

**变更**：
1. 用 `_best_path_ltr` / `_best_path_rtl`（带 memo 的递归全路径搜索）替代 `_best_next_info` / `_best_prev_info`（1-step lookahead）
2. 评分公式：`score = len(current) + max_future_coverage`，其中 max_future_coverage 是对所有候选分支走到底算出的最优总覆盖
3. 保留上一版本的所有其他改动（无 affix 加分、strip 前缀、RTL 定锚）

**触发案例**：`apotheosis` 保持 `apo.the.osis`

| 指标 | 值 |
|---|---|
| 精确匹配 | 55 / 125 |
| 精确匹配率 | **44.0%** |
| 失配 | 70 |

---

### v1.4 — 取消 affix 加分 + 同分选长根 + RTL 定右锚点

**变更**：
1. 移除 `_select_best_ltr` / `_select_best_rtl` 中的 affix 加分（0.5/0.3），纯按 `自身长度 + 前看长度` 评分
2. v1.2 的 `strip("-*")` 前缀修复保留
3. v1.3 的 RTL 首轮只定右锚点保留

**触发案例**：`historic` 从 `hi.stor.ic` 修复为 `histor.ic`

| 指标 | 值 |
|---|---|
| 精确匹配 | 56 / 125 |
| 精确匹配率 | **44.8%** |
| 失配 | 69 |

---

### v1.3 — RTL 首轮只定右锚点（首个匹配后即停）

**变更**：`_match_one_pass` RTL 方向匹配到第一个候选后立即 break，不再继续向左扫描。剩余左侧文本整体标记为 unknown，交由交替循环的 LTR 处理。

**触发案例**：`apotheosis` 从 `ap.othe.osis` 改善为 `apo.the.osis`

| 指标 | 值 |
|---|---|
| 精确匹配 | 52 / 125 |
| 精确匹配率 | **41.6%** |
| 失配 | 73 |

**分析**：RTL 全扫描虽然有时吞了左侧空间，但同时也帮 LTR 确立了多级边界。只定右锚点后，LTR 面对大块未知段更容易误切。多数新失配源于 LTR 首轮选错了根。

---

### v1.2 — 同分选长根（self-first）+ 前缀尾部连字符剥离

**变更**：
1. `_select_best_ltr` / `_select_best_rtl` 平局时从选短根改为选长根（self-first）
2. `_parse_roots` 中 `lstrip("-*")` → `strip("-*")`，剥离前缀尾部连字符（如 `dem-` → `dem`）

**触发案例**：`demagogue` 现正确拆为 `dem + agogue`（之前 `dem-` 因尾部 `-` 无法匹配）

| 指标 | 值 |
|---|---|
| 精确匹配 | 55 / 125 |
| 精确匹配率 | **44.0%** |
| 失配 | 70 |

**分析**：同分选长根导致整体分片质量下降（52.8% → 44.0%），说明优先让下一步多匹配的策略更优。

---

### v1.1 — 交替方向贪心匹配（1音节整词检查）

**变更**：`_segment_word` 入口处增加 ≤1 音节检查——若整词 ≤1 音节，只在 root_index 中查整词匹配（不进入交替分解）。

**触发案例**：`belie` 的 crosstem 分片 `lie`（1音节）不再被分解为 `l.ie`，保持为 `[lie]`。

| 指标 | 值 |
|---|---|
| 精确匹配 | 66 / 125 |
| 精确匹配率 | **52.8%** |
| 失配 | 59 |

---

### v1 — 交替方向贪心匹配（初始版本）

**算法概要**：
- 初始 RTL 扫描整词 → 进入交替循环（LTR → RTL → LTR → ...）
- 1 步前瞻（lookahead）评分 + affix 加分
- `_match_one_pass` 内：匹配后剩余 ≤1 音节 → 整块留未知，停止
- 交替循环：≤1 音节且不在 root_index 中的段 → 跳过

| 指标 | 值 |
|---|---|
| 精确匹配 | 65 / 125 |
| 精确匹配率 | **52.0%** |
| 总失配 | 60 |

**失配分类**：

| 类型 | 计数 | 示例 | 根因 |
|---|---|---|---|
| 短前缀丢失 | ~15 | `a(ver)`, `e(rudite)`, `oc(clude)`, `per(cipient)`, `pro(clivity)`, `ne(farious)` | RTL 优先匹配后缀后，剩下段 ≤1 音节被跳过；短根规则（≤2字）也阻挡 |
| 剩余1音节跳过致前缀丢失 | ~12 | `co(al)esce`, `in(cul)cate`, `(in)effable`, `(in)veterate` | RTL 切走后缀后 1 音节剩余直接被跳过，等不到 LTR 找前缀 |
| 无根整词/碎片 | ~8 | `chicanery`, `harangue`, `mettlesome`, `raconteur`, `craven`, `austere` | 词典中无匹配；算法找到的根是 spurious match |
| 残留单字符 | ~10 | `del[u]ge`, `denig[r]ate`, `[h]ar[ang]ue`, `ext[r]avagance` | 逐字符跳过 + 音节检查只防连续 >1 组的情况 |
| 错配词根 | ~10 | `sanguine`→`san.gui`(×) vs `sangu.ine`(✓), `sycophant`→`sy.coph`(×) vs `syc.o.phant`(✓) | root_index 匹配了字面相似但词源不同的根 |
| 标准粒度过细 | ~5 | `turp.i.tude` vs `turpi.tude`, `voc.i.fer.ous` vs `voci.fero.us` | 算法聚合形式合理但标准不一致 |

**主要短板**：
1. 短前缀（≤2字母）无法被识别
2. 1音节剩余跳过规则同时阻挡了有效前缀搜索
3. root_index 缺少部分常用词根（如 `locut`, `plac`, `calc`, `calc` 等）
4. 逐字符跳过产生大量单字符残留

---

### v0 — 旧版 LTR 贪心匹配（历史参考）

**算法概要**：单次 LTR 扫描，1步前瞻评分 + affix 加分，逐字符跳过。

| 指标 | 值 |
|---|---|
| 精确匹配 | 未标准评分 |
| 已知缺陷 | `hedonist` 切为 `he.donist`，小词（≤5字母）不处理 |

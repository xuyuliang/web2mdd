# 交替方向贪心匹配算法

## 概述

两阶段流水线：Stage 1（派生追溯）→ Stage 2（交替方向词根贪心匹配）。

---

## 音节计数

**规则**：连续元音（`aeiouy`）算一组，一组 = 1 音节。

| 文本 | 元音组 | 音节数 |
|---|---|---|
| ta | a | 1 |
| tha | a | 1 |
| thea | ea | 1 |
| tac | a | 1 |
| tace | a-e | 2 |
| sedulous | e-u-o-u | 4 |
| capr | a | 1 |

y在词语的最左边算辅音。中间和最右边算元音
实现：`_count_syllables(text)` 扫描字符，遇元音且前一个不是元音则计数 +1。

---

## 主入口 `segment(word)`

1. 若整词 ≤1 音节 → 直接返回原词（不处理）
2. Stage 1：查 `word_derivations.json` 追溯派生链，如 `hedonist → hedonic.ism.ist`
3. 将 Stage 1 切分后的每段送入 Stage 2
4. Stage 1 无结果时，整词送入 Stage 2

---

## 两阶段交替 `_segment_word(word)`

```
第一轮：RTL 扫描整词（_match_one_pass）
  → 合并相邻未知段
  → 若 RTL 未命中任何根 → 整词返回未知

第二轮起：交替方向
  → 对每段未知段，若 ≤1 音节且本身不在 root_index 中 → 跳过
  → 否则运行 _match_one_pass(段文本，当前方向)
  → 合并相邻未知段
  → 若有新匹配 → 变换方向，继续
  → 若无新匹配 → 停止
```

方向切换顺序：**RTL → LTR → RTL → LTR → ...** 直至无新匹配。

---

## 单方向匹配 `_match_one_pass(text, direction)`

### LTR（左→右）

```
i = 0
while i < L:
    查找所有从 i 开始的候选根
    若存在：
        评分 → 选最高分 → 标记为已匹配段
        i += 根长度
    若不存在：
        剩余 = text[i:]
        若剩余 ≤1 音节 → 整块标记未知，停止
        否则 → 标记单字符未知，i += 1
```

### RTL（右→左）

```
i = L - 1
while i >= 0:
    查找所有以 i 结尾的候选根
    若存在：
        评分 → 选最高分 → 标记为已匹配段
        i = 根起始位置 - 1
        若剩余 text[:i+1] ≤1 音节 → 整块标记未知，停止
    若不存在：
        剩余 = text[:i]
        若剩余 ≤1 音节 → 整块 text[:i+1] 标记未知，停止
        否则 → 标记单字符未知，i -= 1
```

---

## 评分公式

LTR：

```
score = len(root) + max_len_starting_at(pos + len(root))
        + (is_affix ? 0.5 : 0)
        + (next_is_affix ? 0.3 : 0)
```

RTL：

```
score = len(root) + max_len_ending_at(pos - len(root))
        + (is_affix ? 0.5 : 0)
        + (prev_is_affix ? 0.3 : 0)
```

评分策略：1 步前瞻（lookahead）+ 来源加分。后缀因 affix 加分更易被选中。

---

## 短根限制（≤2 字母）

- **LTR**：只允许在段首（pos=0）或紧邻左侧已匹配段
- **RTL**：只允许在段尾（pos=L-1）或紧邻右侧已匹配段

防止 `tt`、`is` 等短串的误匹配。

---

## 1 音节段跳过规则

在交替循环中，若未知段 ≤1 音节且本身不在 `root_index` 中，则跳过不处理。
已在 `root_index` 中的 1 音节段（如 `ab`、`ad`、`am`）仍会被匹配。

在 `_match_one_pass` 中，匹配后/跳过后的剩余文本若 ≤1 音节，则整块留为未知并结束当前方向扫描。这防止了类似 `censure → cens + ure` 场景中 `cens` 被逐字符分解。

## 处理示例

### `censure`

| 步骤 | 操作 | 结果 |
|---|---|---|
| RTL 整词 | 自右匹配 `ure`（len=3）| 剩余 `cens` |

    剩余 `cens`（1 音节）→ 在 `_match_one_pass` 中停止，整块留未知

| LTR 遍历 | `cens` ≤1 音节且不在 root_index → 跳过 | - |
| 最终 | | `[cens].ure{d}` |

### `aberration`

| 步骤 | 操作 | 结果 |
|---|---|---|
| RTL 整词 | 自右匹配 `ion` → `errat`，剩余 `ab` | `ab` + `errat` + `ion` |
| LTR | `ab`（1 音节，在 root_index）→ 匹配 | `ab{d}` |
| 最终 | | `ab{d}.errat{d}.ion{d}` |

### `hedonist`

| 步骤 | 操作 | 结果 |
|---|---|---|
| Stage 1 | `hedonic.ism.ist` | 拆为 `hedonic`, `ism`, `ist` |
| RTL on `hedonic` | 自右匹配 `ic` ← `on` ← `hed` | `hed` + `on` + `ic` |
| RTL on `ism` | 1 音节不在 root_index → 跳过 | `ism` 未知 |
| RTL on `ist` | 匹配 `ist`（在 affix） | `ist{a}` |
| 最终 | | `hed{d}.on{a}.ist{a}` |

### `capricious`

|---|---|---|
| RTL | 自右匹配 `ious` ← `ic` ← `capr` | 整词覆盖 |
| 无未知段 | 停止 | `capr{d}.ic{a}.ious{a}` |

## 增补 （已实现）
### 统一词根数据 roots.json
edict（etym-dictionary.json）与 affixes.json 已合并为单一数据源 `data/roots.json`，由
`scripts/build_merged_roots.py` 生成：

```json
"abdom": {
  "ext": "=en -in",
  "meaning": "The abdomen",
  "lang": "L",
  "ety_meaning": "The abdomen",
  "ety_lang": "L",
  "forms": {
    "abdom":   {"opt": false},
    "abdomen": {"opt": false},
    "abdomin": {"opt": true}
  }
}
```

- `ext`：保留 edict 的扩展标示，`-` 可选 / `=` 固有，`*` 为发音补充（opt 语义）
- `forms[form].opt`：false = 本尊或固有扩展（=` 标记），true = 可选扩展（`-`/`*`）
- `forms[form].pos`：affix 的位置标示（`["prefix"]`/`["root"]`/`["suffix"]`）；edict 侧默认不设 pos
- 同一词根在 edict 与 affixes 都出现时，两个性质都保留（ext 走 edict，pos 走 affix）
- 统计：8380 基础根（6736 个 ety 组 + 1644 个纯 affix 独立根），15367 词形

### 运行时索引
`_load_unified_index` 将 `roots.json` 展平为 `form -> [interpretation]` dict，O(1) 前缀探测：
interpretation = {base, opt, pos(frozenset), meaning, lang, src}。
`src` = `"dict"`（有 ety_meaning）或 `"affix"`。单字符词形（len<2）不载入索引。

三条加载规则：
- **统一小写**：词形先转小写再载入（`I` → `io`/`ion`），len<2 过滤在转换前，避免 `"I"`（1 字符）泄漏为 `"i"`。
- **self 形式优先**：同一词形命中多个 base 时，`base.lower() == form` 的自形排最前（stable sort），
  防止小写化后 `I`（"A hundred"）的词形 `io`/`ion` 劫持真正 `-ion`/`-io` 根的释义。
- **展示释义**：`src == "dict"` 且 `ety_meaning` 干净（不含 `see also`/`;;`）时用 `ety_meaning` + `ety_lang`，
  否则回退 `meaning` + `lang`；`affix` 侧恒用 `meaning`。

### opt 降权（评分）
`_candidate_score(text, cov, high_freq, opt)` 中，候选词形为可选扩展（`forms[form].opt == true`）时
评分扣 `OPT_PENALTY`（当前 0.5）。动机：`-ion`/`-ous` 等高频后缀常标 opt，避免高频 +0.5 过度奖励。
实测 0.75/0.5/0.25/0.1/0.05 均使 human 61→59（net -2，只改善 gregarious），取用户指定 0.5。

### 前后缀位置约束
`_pos_allowed`：纯前缀不能在词尾（abs_pos + len == word_len），纯后缀不能在词首（abs_pos == 0），
其余位置不限。Stage 1 子片段携带绝对偏移（`_apply_stage1_split` 返回 `(piece, offset)`），
子片段内部匹配也用整词绝对坐标判断，避免 `ence`（后缀）在子片段词首被误拦。

### 长词根优先 / 可选扩展
`ext` 的 `=` 固有扩展在整词命中时优先（如 `abdomen` 直接命中而非拆成 `abdom`+`en`）。

### 前瞻打分（_best_path）
- 前瞻用 `relax_short=True`：放宽 ≤2 字母根的护栏，让 `ex`+`ig` 能击败 `exi`（`exigent → ex.ig.ent`）
- 前瞻与真实匹配分离：真实匹配 `_match_one_pass` 仍用收紧的短根护栏（短根需在段首或紧邻已匹配段）
- 候选评分返回 `(覆盖长度, 段数, edge_short)`，edge_short = 最优路径是否依赖子串边缘的 2 字母根

### 候选选择 tie-break（_select_best_*）
同级分按四级裁决：
1. 覆盖长度（len(root) + 续接覆盖）更大优先
2. 段数更少优先（`corroborate → cor.robor.ate` 而非 `corr.ob.or.ate`）
3. 不依赖边缘短根优先（`percipient → per.cip.ient` 而非 `perc.ip.ient`）
4. 词根更长优先（`discern → dis.cern` 而非 `disc.ern`）

### 已删除
- `_resolve_overlaps`：在新 src 语义下过度触发（会把 `nefarious` 切成 `ne.fa.r.ious`），已整体移除
- `_best_next_info` / `_best_prev_info`：死代码

### 已知局限
- 词根末字符与后缀首字符重叠（如 `sanguine = sangui + ine`）无法还原，得 `san.[gu].ine`
- 噪音短根（如 `ip`=worm）与真短根（如 `ig`）结构同型，结构性不可区分

## 未实现规划
以下为文档早前记录的设想，尚未在代码中实现。

### gap 扣分的宽容度（垫音 gap 字母）—— 未实现
考虑到英语会在词根词缀之间插入一个字母，纯粹缓解发音（如 `ology` 与 `logy` 的 `o`，有时删去一个重复字母，
有时用 `e` 代替 `ex`）。设想：填补词根词缀后，若中间的 gap 只有 1 个字母，不扣分，并且根据它是元音还是辅音、
它左右两边是元音还是辅音，做恰当的合并（并入左侧或右侧，凑成"辅音+元音"音节）。当前代码中不存在此规则，
单字符 gap 会原样留在切分里显示为 `[x]`。

优先级应该这样：
比如留空要扣1分的话，垫音只扣0.5分。 
目的是：
垫音是无奈之举，但是比留空好。

### 高频前后缀优先（+0.5 分）
`data/high-freq-affixes.json`（常见高频前后缀，含中文释义与示例）已接入主算法：`WordCutter.__init__` 通过
`_load_high_freq` 将 `affix` 剥离横杠、转小写后收集为 `form -> frozenset(type)` 的高频位置映射
（len<2 跳过，与 root_index 口径一致），`self.high_freq` 为其键集合。

两条配套规则：
1. **加分**：在真实匹配的决策点 `_select_best_ltr/_select_best_rtl` 中，候选词形命中高频集合时评分 +0.5 分；
   前瞻 `_best_path_*` 不参与加分。
2. **位置约束**（`_hf_pos_allowed`）：高频映射中 `type` 仅为 `prefix` 的词形只能在词首（`abs_pos == 0`），
   仅为 `suffix` 的只能在词尾（`abs_pos + rlen == word_len`），两者皆有则不限。在 `_find_candidates_ltr/_rtl`
   中与通用 `_pos_allowed` 一并过滤，真实匹配与前瞻一致。这阻止了 `anim → an.im`（`im` 为纯高频前缀，
   不得出现在词尾）。

回归：`test-word-cut` 命中 123/125 不变，`score_vs_human` 57→61/125，`score_against_standard` 56→57/125。
